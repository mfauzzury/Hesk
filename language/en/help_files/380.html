Interactive help for Hesk settings

 

Enable password expiration

This feature improves account security by requiring users to change their password after a set period of time.

It can help reduce the risk of unauthorized access caused by long-term password reuse, leaked credentials, or compromised accounts.

You can configure separate password expiration periods for:

  • Staff accounts
  • Customer accounts

Password complexity

This feature lets you define minimum security requirements for user passwords.

You can configure:

  • Minimum password length
  • Minimum number of lowercase letters
  • Minimum number of uppercase letters
  • Minimum number of numbers
  • Minimum number of special characters
  • Do not allow reuse of the last X passwords
  • Detect and block common / weak passwords

Passwords must meet all configured requirements before they are accepted.

Force password expiration

This tool lets administrators immediately expire all staff or customer passwords.

After passwords are expired, affected users must reset their password before they can log in again.

This can be useful in situations such as:

  • A suspected security breach
  • Password policy changes
  • Periodic mandatory password resets
  • Employee offboarding
  • Company-wide security enforcement

Allowed customer email domains

Use this setting to restrict email domains for new customer registrations and new tickets from unregistered customers, including tickets submitted by email.

Leave the list empty to allow all domains. Otherwise, enter one domain per line, for example:

example.com
school.example

Domains match exactly, without regard to case. List subdomains separately, for example support.example.com. Wildcards such as *.example.com are not supported.

This setting does not change Require email. If email is optional, customers can submit a ticket without an email address. If they provide an address, it must be valid and its domain must be allowed.

New customer registrations still require an email address. Incoming email must have a valid sender address.

Existing registered customers retain their usual access, including submitting new tickets. Existing ticket replies, followers, customer profile changes, and customers or tickets created by staff are unaffected.

Remove email subject prefixes

Remove known banners from the subjects of new tickets created by email piping, POP3 or IMAP fetching. Leave the list empty to disable this feature.

Enter one literal prefix per line, for example:

[EXTERNAL]
[*** CAUTION: EXTERNAL MAIL ***]

Each entry is removed wherever it appears in the subject. Matching is case-sensitive and treats entries as literal text. Wildcards and regular expressions are not used. Blank lines are ignored, and spaces around each entry are removed.

For example, with [EXTERNAL] configured, [EXTERNAL] Printer problem becomes Printer problem. The text [external] is kept because the letter case differs.
